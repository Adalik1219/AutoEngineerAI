## Acceptance criteria (kazde ma jasny PASS/FAIL + meritelny dukaz)

Spolecne: Play Solo, reclaim (0 cizich dilu), telemetrie + RAW archiv jako run-003,
testy na trati +X s rezervou. Nevyhovujici vysledek = FAIL kriteria (ne cele F7.2).

### AC1 — Zataceni vlevo (steer -1)
- Postup: primy rozjezd na v≈25, drzet steer=-1 po 3 s (stream 0.2 s).
- PASS: |Δyaw| >= 0.15 rad a lateralni posun >= 8 coule za 3 s; dukaz: yaw
  vzorky + trajektorie (x,z) z telemetrie. Jinak FAIL.

### AC2 — Zataceni vpravo (steer +1)
- Stejny postup zrcadlove.
- PASS: stejne prahy jako AC1 + symetrie: |vysledek_L| vs |vysledek_R|
  v toleranci ±20 %. Jinak FAIL.

### AC3 — Opakovatelnost (relativni rozpeti)
- 3 opakovani pro kazdy smer (celkem 6 jizd), stejne podminky.
- Pro kazdy smer a pro kazdou velicinu zvlast (Δyaw; lateralni posun):
  R = (max - min) / |mean| * 100 %.
- PASS: R_yaw <= 10 % A R_lat <= 10 % v obou smerech.
  Jinak FAIL (+ vysetrit outlier, neusmernovat).
- Poznamka: prahove minima AC1/AC2 (0.15 rad / 8 coule) drzi |mean| mimo
  nulu, takze R je dobre definovane; pri nesplneni prahu AC1/AC2 se AC3 nehodnoti.

### AC4 — Uvolneni steering vstupu (vcetne ridiciho vystupu)
- A-Chassis 'New' rizeni je kinematicke (absolutni CFrame zapis, zadny momentovy
  kloub) — ridicim vystupem je uhel natoceni Arm.Steer, ne moment. Overuje se
  navrat uhlu, ne moment.
- Po ukonceni streamu (ticho na lince) sledovat 2 s.
- PASS soucasne: (a) |yaw_rate| < 0.02 rad/s do 1.5 s po uvolneni;
  (b) uhel natoceni kazdeho predniho Arm.Steer zpet na |uhel| < 0.5°;
  (c) AE_Steer -> 0/nil a AE_SteerC -> 0 (dead-man neutral);
  (d) vuz nepokracuje v zataceni. Jinak FAIL.

### AC5 — Ztrata spojeni a stale prikazy (explicitni odmitnuti)
- (a) Ztrata: 2 s ticha -> dead-man neutral do 1.0 s (AE_Throttle/AE_Steer 0,
  #AV moment 0). Dukaz: snimky atributu s casem.
- (b) Stale: stejny seq dvakrat s ruznou hodnotou -> druhy prikaz je
  EXPLICITNE odmitnut: nezmeni ZADNY ridici atribut (AE_Throttle/AE_Brake/
  AE_Steer), neprepise stav smycky (entry zustava), a neozivi rizeni po
  dead-manu (povel se starym seq po tichu -> stav zustava neutral, #AV = 0).
  Dukaz: before/after snimky atributu + stavu.
- PASS: obe casti splneny. Jinak FAIL. (F7.1: stale = CODE-VERIFIED,
  tento runtime test je jeho doplnenim.)

### AC6 — Occupant/seat autorizace (vychozi politika Occupant-only, zesilena)
- Vychozi politika: manualni povely pres AEDriveCmd prijima server POUZE,
  je-li splneno SOUCASNE: (a) `DriveSeat.Occupant ~= nil`; (b) Occupant je
  Humanoid hrace, ktery povel poslal (`player.Character.Humanoid ==
  seat.Occupant`); (c) sedadlo patri ridizenemu vozidlu (vozidlo se neurcuje
  globalnim slotem, ale vystupem od sedadla hrace: Humanoid.SeatPart -> seat
  -> AE slot; sedi-li hrac v cizim/ne-AE vozidle, povel se odmitne).
  Pripadne uvolneni politiky je samostatne rozhodnuti, ne tichy ustupek.
- Testy (Occupant vlastnost citne v kazdem kroku):
  (i) hrac sedi ve vozidle + vlastni povel -> PRIJATO (pohyb dle AC1);
  (ii) nikdo nesedi + povel -> ODMITNUTO (atributy i fyzika beze zmeny);
  (iii) A sedi, B posila povely -> ODMITNUTO. Solo-session ma jednoho hrace,
  proto (iii) jako RUNTIME s dvema hracemi = PENDING (mimo Solo scope);
  ekvivalent se overi unit-testem autorizacniho predikatu s mocky
  (A-Humanoid == Occupant vs B-Humanoid ~= Occupant -> reject).
- PRUBEZNA autorizace (ne jen pri RemoteEventu): Heartbeat smycka kazdy tick
  overi, ze `seat.Occupant` je porad TEN Humanoid, pro ktery plati entry
  (odchozi hrac / vymena ridice / znicene sedadlo). Pri nesouladu okamzita
  neutralizace: stejny stav jako dead-man (0,0,0 + steerT=0 + narovnani +
  zruseni entry) — BEZ cekani na 1.0s timeout.
- Test vystoupeni: sedi + drzeny povel (stream), hrac opusti sedadlo
  (Occupant -> nil) -> do 5 ticku Heartbeat neutral (AE atributy 0/nil,
  #AV = 0, uhly rampuji k 0 pres ReturnSpeed). Dukaz: snimky + cas.
- PASS: (i) funguje, (ii) bez ucinku, (iii-unit) reject, vystoupeni neutral
  do 5 ticku; (iii-runtime) PENDING explicitne. Jinak FAIL.

### AC7 — Ownership assemblies vs ochrana ridiciho stavu (GetNetworkOwner() == nil)
- Dve oddelene veci: (1) FYZIKALNI AUTORITA (kdo simuluje assembly) vs
  (2) OCHRANA RIDICIHO STAVU (ci zapis plati pro uhel/steerC).
- (1) Ownership: na zacatku a behem kazde steer jizdy se spocitaji UNIKATNI
  assembly roots pres `GetAssemblyRootPart()` pres mnozinu {4 kola, predni
  Arm.Steer, DriveSeat, nosne dilly slotu}; u kazdeho unikatniho rootu se
  zaznamena ANCHORED (bool) a `GetNetworkOwner()`. `nil` na UKOTVENEM dilu
  NENI dukaz serverove simulace pohyblive assembly — ukotveny dil se
  nesimuluje vubec.
- PASS (1) soucasne: (a) vsechny rooty v mnozine jsou UNANCHORED;
  (b) vsechny maji GetNetworkOwner() == nil po celou dobu jizdy.
  Ukotveny root v mnozine vozu = FAIL (anomalie: ukotveny dil vozu;
  zadny waiver bez priciny). Staticke dily trate do mnoziny NEPATRI
  (jejich anchored+nil je ocekavane a nic nedokazuje).
- Riziko neni klientsky CFrame zapis (ten je bez autority zahazen), ale TICHY PRECHOD vlastnictvi
  (auto-assign blizkosti/seatem) — proto se ownership monitoruje prubezne,
  ne jen na zacatku.
- (2) Ridici stav: pokus klienta o zapis CFrame ridiciho dilu je test
  INTEGRITY STAVU, ne dukaz prevzeti ownership (klient SetNetworkOwner volat
  nemuze — server-only API). PASS: uhel/steerC/AE_SteerC drzi serverovou
  hodnotu v nasledujicich ticich (klientsky poke bez trvaleho ucinku).
- PASS soucasne: (a) PASS (1) vyse (unanchored + nil-server po celou dobu);
  (b) client poke bez trvaleho ucinku; (c) AC1/AC2 PASS pri inertnim
  client-Drive. Jinak FAIL.

### Vazba na A-Chassis (overeno ctenim sablony, Build 6C v1.5u2.1)
- Zdroj: `Drive` LocalScript, blok `[[Steering]]` (r. 322+), Tune `[[Steering]]`
  (r. 108-142). Aktualni hodnoty vozu: SteeringType='New', SteerRatio=15,
  LockToLock=2.6, Ackerman=0.9, SteerSpeed=0.05, ReturnSpeed=0.1,
  SteerDecay=330, MinSteer=10 %, FWSteer='None' (zadni rizeni vypnuto).
- Odvozene konstanty (stejny vzorec jako Drive r. 325-326):
  SteerOuter = (2.6*180)/15 = 31.2°; SteerInner = min(31.2-31.2*0.1, 31.2*1.2)
  = 28.08°.
- Klientsky Drive (r. 344-356) rampuje `_GSteerC -> _GSteerT` (SteerSpeed ven,

  `v.Arm.Steer.CFrame = Base.CFrame * Angles(0, -rad(_GSteerC * Inner/Outer *
  sDecay), 0)`, vnitrni/vnejsi kolo dle znamenka (Ackermann). Stav publikuje
  do `Values.SteerC` (r. 1175), kterou cte i SS6 Dynamic Friction (smyk).

### Fyzikalni princip navrhovaneho aktuatoru
- Stejny kinematicky princip jako A-Chassis 'New': natoceni prednich kol
  (cepi `Arm.Steer` kolem lokalni Y osy zakladny kola) meni rovinu kola;
  bocni sila pneumatiky (SS6 friction) pak staci vuz do zatacky.
  ZADNY novy momentovy kloub, zadna zmena geometrie podvozku.
- Rozdil oproti klientovi: zapis provadi SERVER (vlastnik fyziky), takze
  replikuje a pretrva; klientsky Drive zustava zdrojem NULA (mrtvy v teto
  session, jinak by jeho zapisy server zahazoval).

### Zpusob rizeni (ServerSteer.Step)
- Nova funkce `ServerSteer.Step(vehicle, steerT, dt)` (soucast ServerDrive

  1. Prikaz: `steerT` = uz validovany/clampnuty AE_Steer (-1..1) z AEDriveCmd
     (manual) nebo z replay-scenare (budouci T-steer).
  2. Stav `steerC` na vozidlo (modulova tabulka, analogie `_states` pohonu);
     rampa presne dle Drive: SteerSpeed ven / ReturnSpeed zpet, s `dt`.
  3. `sDecay` z rychlosti sedadla, prah MinSteer; konstanty SteerInner/Outer
     z Tune (ctene existujici Tune-cestou, zadny hardcode).
  4. Zapis: pro kazdou predni sadu {F, FL, FR} existujici ve voze doslovny port
     Drive r. 363-380 (vnitrek/vnejsek dle znamenka steerC; R-sada VYNECHANA,
     FWSteer='None').
  5. Publikace: `AE_SteerC` (aktual, pro telemetrii/AC4) + `Values.SteerC`
     (pro SS6 friction, stejny kanal jako klient) + `AE_Steer` zustava prikaz.
- Volano z: (a) manual-loop Heartbeat (stejny tick jako plyn/brzda);
  (b) budoucich replay-scenaru; NIKDY primo z klienta.

### Bezpecne uvolneni (release / stale / dead-man / prevzeti replayi / VYSTOUPENI)
- Nulovy prikaz (release, dead-man, ClearDriveInputs, stale-odmitnuti) =
  `steerT = 0`: steerC rampuje zpet pres ReturnSpeed (ZADNY skok na 0, zadne
  trhnuti volantem), CFrame se narovna, SS6 dostane SteerC -> 0.
- VYSTOUPENI ridice behem aktivniho povelu = okamzita neutralizace BEZ cekani
  na dead-man timeout: prubezna autorizace v Heartbeat (viz AC6) pri
  nesouladu zrusi entry + nastavi klidovy stav (0,0,0 + steerT=0 + narovnani).
  Duvod: opustene vozidlo s drzenym plynem/rejdem je nebezpecny stav.
- Stale povel se vubec nedostane do smycky (entry neprepsano, stav drzi
  posledni platny prikaz nebo neutral po dead-manu).
- Prevzeti replay-scenarem (activeVehicles): manualni entry se ignoruje,
  steerC prebira scenar; po konci scenare ClearDriveInputs (+ narovnani).
- Verifikace uvolneni = AC4 (uhel < 0.5°, yaw_rate, AE_SteerC = 0).
- Fail-safe: chybi-li `Arm.Steer` nebo `Base` (nekompletni stavba), Step vrati
  false + warn (zadny castecny zapis na jedno kolo); zadne tiche rizeni.

## Technicky dodatek (dolozene fakty, ke kontrole)

### D1 — Presna originalni rampa _GSteerC (Drive r. 329-330, 344-356)
Doslovny port, pouze prejmenovane vstupy (`steerC`, `steerT` misto `_GSteerC`,
`_GSteerT`; `rate` z Tune):
```
-- Drive: deltaTime = (60/(1/dt))  (≈1.0 pri 60 fps; dt = skutecny cas snimku)
-- Server: ticks = dtHeartbeat * 60  (dt merene, nezavisle na frekvenci)
if steerC < steerT then
  steerC = (steerC < 0) and math.min(steerT, steerC + ReturnSpeed*ticks)
                        or math.min(steerT, steerC + SteerSpeed*ticks)
else
  steerC = (steerC > 0) and math.max(steerT, steerC - ReturnSpeed*ticks)
                        or math.max(steerT, steerC - SteerSpeed*ticks)
end
```
- Chovani identicke s klientem pri libovolnem fps: `ticks` normalizuje prirustek
  na 60Hz-ticky (stejne jako `deltaTime` v Drive). Pri Heartbeat 60 Hz je
  `ticks ≈ 1.0`; pri kolisani fps se rampa zrychli/zpomaly presne jako klientovi.
- OCHRANA PRED VYPADKEM (zamerna odchylka od klienta, dokumentovana): klient
  `deltaTime` nema strop (po hitchi skok rejdu). Server pouzije
  `ticks = math.min(math.max(dtHeartbeat * 60, 0), 3)`:
  bezny provoz (ticks ≈ 1) = bitova ekvivalence s klientem; vypadek Heartbeat
  (>50 ms) rampu ZPOMALI misto skoku (max 3/60s prispevku na tick). Zdanlive
  "zpozdeni" po vypadku je spravne — bezpecnost pred synchronnosti.
- Hodnoty vozu: SteerSpeed=0.05, ReturnSpeed=0.1 (jednotky prikazu -1..1 na
  60Hz-tick; plny rejd za ~20 ticku, navrat za ~10).

### D2 — CFrame a struktura (proc zapis neprepisuje odpruzeni)
- Jediny zapisovac `Arm.Steer.CFrame` v cele hre je blok Drive r. 365-426
  (overeno scr-grepem pres vsechny skripty vc. Initialize a pluginu).
- Zapis je KOMPOZICE s aktualni zakladnou, ctenou CERSTVE kazdy tick:
  `Steer.CFrame = Base.CFrame * Angles(...)`. Odpruzeni hybe s `Base`
  libovolne; server pridava pouze natoceni. ZADNE cachovani Base.CFrame mezi
  ticky (jinak by zamrzlo odpruzeni) — cist pri kazdem Stepu znovu.
- Mnozina ridizenych kol se neurcuje hardcodem, ale pritomnosti slozek
  {F, FL, FR} ve `Wheels` v BEHU (doslovne vetveni Drive r. 363-377,
  vnitrek/vnejsek dle znamenka steerC; R-sada VYNECHANA, FWSteer='None').
  Chybi-li `Arm`, `Steer` nebo `Base` u nektere sady -> Step vrati false +
  warn, ZADNY zapis (fail-closed, zadne castecne rizeni).
- Poznamka ke strukture: sablona (.rbxm i live Edit) obsahuje jen hola kola
  FL/FR/RL/RR; `Arm`/`Steer`/`Base` stavi Initialize za behu (dukaz: slot mel
  v Play 901 dilu + 4x #AV). Seznam kol v navrhu proto odpovida BEHOVE
  strukture (K1: predni = FL/FR/F), ne Edit-sabloně.

### D3 — Mereni uhlu (AC4, relativni, vsechna ridizena kola)
- Uhel kola i = Y-slozka z `(Base.CFrame:ToObjectSpace(Steer.CFrame)):ToOrientation()`,
  pro kazdou pritomnou predni sadu zvlast (F/FL/FR).
- Ocekavana hodnota behem drzeni: `steerC * Inner/Outer * sDecay` (Inner/Outer
  dle znamenka, vzorce Drive r. 368-376); tolerance mereni ±1.0°.
- Po uvolneni: vsechny ridizene uhly < 0.5° (AC4b). Merici kanal: telemetrie
  (vzorky uhlu + steerC + yaw) + RAW.

### D4 — Fyzikalni validace T0 (BRANA pred AC1-AC7)
CFrame zapis na serveru NENI dukaz zataceni. Po implementaci nejprve
samostatny test T0, staticky i pomaly:
- T0-a (statika, v=0): drzet steer ±1; overit: uhly dosahnou cilu
  (sDecay≈1 -> plny Inner/Outer), symetrie L/R, Base se neposunula
  (translacni delta Base.CFrame pred/po ≈ 0 — odpruzeni nedotceno),
  zadne nove kontakty, pocet dilu a #AV/#BV beze zmeny.
- T0-b (stabilita): drzet plny rejd 5 s pri v=0; uhly stabilni (smerodatna
  odchylka mala, zadna oscilace/divergence), zadna exploze sestavy
  (max rychlost dilu rozumna), po release navrat dle AC4.
- T0-c (cela sestava pri jizde): kratky primy rozjezd s rejdovanymi koly
  pri nizke rychlosti; vuz se rozjede a ZACNE menit heading; kola zustavaji
  v sestave (Base relativne k sedadlu stabilni ± tolerance), zadne odtrzeni.
- T0-d (DYNAMIKA odpruzeni — komprese/odlehceni; staticke delta nestaci):
  brzdny manevr z nizke rychlosti (dive) + rozjezd (squat) ve dvou variantach:
  (A) steer = 0, (B) steer = ±1 drzen. Sledovat po celou dobu: relativni
  transformaci Base vuci kolu (vzdalenost Base↔stred kola v case = prubeh
  zdvihu), amplitudu komprese predek/zadek, integritu kloubu (#AV/#BV pritomny,
  zadne nove kontakty), stabilitu sestavy (zadna divergence, zadne odtrzeni).
  PASS T0-d: amplituda komprese s rejdem v ±15 % amplitudy bez rejdu;
  po zastaveni navrat na statickou vysku ± tolerance; AC4 uhly plati i po
  dynamice. FAIL = rejd vaze/prida tuhost odpruzeni nebo narusuje klouby.
- PASS T0 = vsechny ctyri casti (a-d); teprve pak AC1-AC7. FAIL = stop,
- diagnostika (podezreli: spatna osa cepu, svadleny Steer, konflikt
- s pluginem, vazani odpruzeni), zadne pokracovani na dynamicke testy.
